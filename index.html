August 11 meeting notes

Meeting: OH Build Guild Monthly Series
Topic: GitHub Copilot token optimization, agent quality, and cost management
Presenters: Kennedy, Ricardo Wilkins, Al Barnes, August Spinks, and Madiha Khan

Executive summary

The session focused on how GitHub Copilot users can maximize value from AI credits by improving agent quality and prompt efficiency, rather than simply minimizing token consumption. The presenters argued that the goal should be to make every token count by providing better context, choosing appropriate models, managing context windows, and using instructions, skills, and agents effectively.

Key takeaways

  • Focus on quality, not just cost: “Token optimization” should mean improving outcomes and ROI, not simply reducing spend. Higher quality prompts and workflows reduce rework and prevent repeated prompting.
  • Avoid “agent gambling”: Create better prompts up front, add appropriate guardrails, use skills and custom agents, and treat prompting more like planning a mission than trial and error.
  • Bad AI output compounds over time: Validate outputs early, test frequently, and avoid letting agents continue building on questionable results.

How context windows affect results

Give: “As little context as possible, but as much as required.”

  • Don't attach entire repositories unnecessarily.
  • Attach files you already know are relevant.
  • Highlight specific files or code ranges when possible.
  • Reduce agent reasoning work by supplying obvious context yourself.

Start new sessions frequently

Previous conversation history is sent back with every prompt in a session, creating cached context that grows over time. For unrelated tasks, start a new session, such as for a bug fix, documentation task, or new feature. This prevents unnecessary context growth and token consumption.

Context window biases

  • Lost-in-the-middle bias: When a session grows, the model can lose track of instructions in the middle of the conversation and revert to earlier topics. Start a new session when changing tasks.
  • Recency bias: Once a context window exceeds roughly 50% utilization, models increasingly prioritize recent content and may forget earlier instructions, skills, or system guidance. Keep context windows under about 60–70% utilization when possible.

The two biggest cost levers

  • Model selection: Use high-reasoning models for architecture, planning, complex debugging, and large modernization efforts. Use lightweight or mid-tier models for implementation once a plan is established. Consider Auto Mode, which selects models automatically and provides a token discount.
  • Context engineering: Become effective “context engineers” by deciding what files to include, what instructions to provide, what skills to activate, and what context to leave out. Provide enough information for success without overwhelming the model.

Practical prompting recommendations

  • Be specific: Instead of “Fix the bug,” identify the issue and describe the observed behavior.
  • Add stop conditions: Explicitly tell Copilot when to stop, such as “Fix the bug and stop,” “Make the change but don't commit,” or “Return only code.”
  • Provide known context up front: Attach relevant files and documentation instead of forcing Copilot to discover them through additional reasoning.

Skills, instructions, MCPs, and agents

  • Copilot instructions: Use concise persistent instructions for coding standards, required guardrails, output formatting, and common mistakes to avoid. Keep them short because they are loaded into every session.
  • Skills: Create skills only for knowledge Copilot wouldn't naturally know, and avoid creating skills for common frameworks unless they contain organization-specific guidance.
  • MCP servers: MCPs can be powerful but expensive. Disable unused MCPs, enable only required tools, and consider CLI alternatives where available because they can be more token-efficient.

Testing strategy

Implement → Test → Implement → Test

Testing incrementally instead of implementing everything and testing once at the end limits the impact of compound errors and catches problems earlier.

Interesting example shared

The presenters described a case where a user asked Copilot to compare two Excel files directly. Instead, they instructed Copilot to generate a script that compares the files, run the script, and review the output. This completed faster and used fewer tokens because the work shifted into code execution rather than large-scale agent reasoning.

Top 5 actions recommended

  1. Choose the right model for the task.
  2. Use clear, specific prompts.
  3. Plan before implementation.
  4. Create effective guardrails through instructions and skills.
  5. Keep Copilot instruction files concise and focused.

Bottom line: Successful GitHub Copilot usage is increasingly about context engineering and workflow design, not simply picking the smartest model. Teams that provide cleaner context, better prompts, and tighter guardrails will achieve better code quality, lower token usage, and higher ROI.

September 8 meeting notes

Discussion

  • Token Optimization Strategies in GitHub Copilot: Ricardo, Kennedy, Al, August, and Thomas discussed various strategies for optimizing token usage in GitHub Copilot, including plan mode, model selection, and practical experiences from refactoring large codebases, with Thomas sharing their team's approach and challenges.
    • Plan Mode Versus Agent Mode: Ricardo explained the benefits of starting sessions in plan mode within GitHub Copilot, which allows for ideation and planning before implementation, potentially reducing token consumption and costs by using less expensive models for planning and more powerful models for execution.
    • Model Selection and Cost Optimization: Ricardo highlighted the “auto” model selection feature in GitHub Copilot, which automatically chooses the most appropriate model for a given task, offering a discount and helping users optimize costs by matching model complexity to task requirements.
    • Refactoring Large Codebases: Thomas described their team's use of GitHub Copilot and other AI tools to refactor enterprise Java beans and clean up technical debt, noting that while token consumption was high, the process was faster and cheaper than manual rewriting, and sharing challenges with maintaining context across multiple steps.
    • Managing Context Loss in Multi-Step Tasks: Thomas and Ricardo discussed issues where Copilot loses context after several steps in a refactoring process, suggesting that breaking tasks into smaller, well-defined chunks may help maintain context and reduce token waste.
    • Impact Dashboard and ROI Measurement: Al introduced the impact dashboard, which allows users to input their efforts and receive feedback on the ROI, time savings, and overall impact of using GitHub Copilot, providing a quantitative measure for optimization strategies.
  • Use Cases and Personas for GitHub Copilot: Kennedy presented common use cases for GitHub Copilot, such as code completion, documentation, SQL query optimization, and skill learning, encouraging participants to identify their roles and explore new ways to leverage Copilot, with internal examples of automation and skill sharing.
    • Common Use Cases: Kennedy showcased three slides outlining typical use cases for GitHub Copilot, including code completion, documentation generation, SQL query optimization, and learning new skills, emphasizing the versatility of Copilot across different development tasks.
    • Role-Based Application: Kennedy encouraged participants to consider their specific roles and how Copilot could be tailored to their needs, suggesting that identifying relevant use cases by persona can help users discover new ways to benefit from the tool.
    • Internal Automation and Skill Sharing: Kennedy described how Microsoft teams internally create and share automations and skills, starting from individual contributions and expanding to team-wide repositories, fostering a collaborative environment for skill development and tool integration.
  • Agentic Coding and GitHub Copilot App Interfaces: August and Ricardo discussed the evolution of agentic coding in GitHub Copilot, highlighting the standalone app, agent window, and CLI interfaces, and explaining how these tools support orchestration, session management, and outcome-focused workflows for diverse user roles.
    • Agent Window and Session Management: August demonstrated the agent window in GitHub Copilot, which provides a session-based, outcome-focused interface where agents handle coding tasks, allowing users to manage projects, view chats, and configure settings for plugins and skills.
    • Standalone App Versus IDE Integration: Ricardo and August compared the GitHub Copilot standalone app with IDE integrations like Visual Studio and VS Code, noting that the app offers a more conversational, agent-first approach, while IDE integrations cater to code-centric workflows.
    • CLI and Automation Capabilities: August explained that the CLI interface is favored by platform engineers and those needing automation, while the agent window and app are more suited for outcome-driven tasks, with flexibility to choose based on user comfort and project requirements.
    • Autopilot Mode and Technical Debt Management: August described the autopilot mode in the agent window, which enables fully autonomous coding sessions focused on producing pull requests and documentation, aiming to reduce technical debt and streamline future codebase onboarding.
